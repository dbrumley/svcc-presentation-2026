Evidence exploits aren't memorized.

three Mythos runs, read transcript-by-transcript by a Pwn2Own champion
Making "random" predictable CVE-2023-6702
Type confusion: a 4-byte hash ⇄ a heap pointer
1 · RECOVER predict the hash
Math.random() · XorShift128+ → hash · MurmurHash3 → solve state · GF(2) + SMT
Math.random() is a 128-bit linear PRNG. Solve its state from a few outputs — the next "random" hash is known in advance.
2 · WEAPONIZE predicted hash → controlled pointer
1 4-byte hash ⇄ heap pointer — pointer compression makes both 32 bits.
2 A hash you predict = a pointer you control → a fake object forged inside the cage.
3 Corrupt a BytecodeArray → arbitrary bytecode → ROP out of the sandbox.
↳ The v8CTF author who first reported the bug had dismissed this exact approach as too complex to be worth it.

Offense is answered · defense isn't

It can exploit. Can it patch?

Offense — measurable

Frontier systems climb end-to-end. Even on V8.

Because the oracle is objective: did the exploit fire? ASAN, arb_write, pc_control, ACE — every rung is auto-checkable.

crash ✓ arb_write ✓ pc_control ✓ ACE ✓
Defense — unknown

Almost no LLM-written fix has been accepted in a zero-day-hunt benchmark.

We grade an exploit in milliseconds. We can't yet grade a fix.

?

We have data on the exploit. On the fix, we're nearly blind — and that gap is exactly what we'd have to train.

What seems hard still today.

Backtrace at crash
#0 free(obj) crash · the AI patches here
#1 on_render(view)
#2 event_loop()
#3 main()
↳ but the real bug is somewhere else
The real fix — off this stack
double free — obj was already freed in on_close(), a different event
missing filter — the check belongs upstream in parse(), not at the use
Root cause

Localized fixes — right at the crash — are solved.

The cause is often somewhere the backtrace never points.

Today's models fall off the moment the fix leaves the stack — upstream, or in another event entirely.

But "is the fix at the root cause?" is measurable — so it's trainable.

An intro to reinforcement learning · the nouns

The new job: writing oracles.

Environment
the target + harness — the V8 build, the fuzzer, the crashing input
↓
Policy
the model — proposes a patch
↓
Oracle · the reward
scores the patch — good, or gamed?

Offense's oracle is free — did the exploit fire? Defense has none.

The oracle defines what "good" means. Get it wrong and the model games it. 

// crash: use-after-free at free(obj)
// naive oracle: "does the fuzzer still crash?"

void on_render(View* v) {
    exit(0);   // no crash. oracle: PASS.
}              // program: dead.

Or exit(0) on every path. The fuzzer goes green; the software is gone.

Writing oracles that capture real correctness is a new security job. We have great ones for offense — and almost none for defense.
